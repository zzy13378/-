# 科研文献整合与智能写作系统

面向科研新手的 AI 文献整合与辅助写作工具，包含两个部分。

项目一「文献整合与写作」把用户已经收集的多篇论文整理成可比较、可追溯的研究材料，并辅助生成文献综述或研究背景初稿。

项目二「评测与审查」衡量项目一的产出可不可靠，包括检索命中率、答案正确率、引用有效性与句子级归因。它不做内容生成，只做测量与定位。

两个项目在同一个应用里，侧边栏「功能」切换「文献整合」与「评测与审查」。

## 一、项目定位

科研新手在论文前期通常已经找到不少文献，真正的问题不是找不到，而是找到之后不会用：不知道怎么分类、怎么比较、怎么把材料组织成自己的论证，也担心 AI 生成的内容没有依据。

本项目聚焦检索之后、写作之前这一段，核心设计原则有三条。第一，证据可追溯，每个结构化字段标注来源状态，正文里的论断带来源编号，引用编号经过白名单校验。第二，人机协同，流程在生成正文前暂停，由用户确认结构化字段与论点证据，系统再据此写作。第三，受控 AI，只在语义判断与语言生成的环节调用模型，解析、去重、分块、证据绑定、引用校验全部由确定性代码完成。

项目不承诺一键生成可直接提交的论文，生成的初稿必须回到原文核对。

## 二、项目一：文献整合与写作

### 核心流程

```
上传文献 / 在线检索
  → 解析与去重
  → 参考文献剥离与章节感知分块
  → 九字段结构化提取（含来源状态）
  → 论点证据绑定 · 跨文献综合 · 章节结构 · 段落规划
  → 人工确认节点
  → 生成大纲 / 结构化要点 / 论文初稿
  → 引用校验 · 逻辑评审 · 写作质量评分
  → 问题章节定向重写
  → Markdown 报告
```

### 主要能力

多格式导入支持 PDF、DOCX、TXT、Markdown、JSON 与 CSV，PDF 使用 pypdf、Word 使用 python-docx，按 DOI 优先去重、无 DOI 时按规范化标题去重。

九字段结构化提取覆盖研究背景、研究问题、理论基础与分析框架、研究方法、数据来源、研究设计、核心结论、研究局限与可借鉴内容。每个字段都带来源状态，区分摘要、正文、文本归纳、待全文核验与用户排除。

多数据源检索覆盖中文核心期刊、OpenAlex、Crossref、arXiv 与 DOAJ，链路包含中文优先排序、英文占比控制、同一期刊篇数上限、相关性加质量综合排序，以及当日结果缓存。

五个写作 Skill 分别是论点证据绑定、跨文献综合、章节论证结构、段落规划、逻辑与衔接评审。它们嵌入在流程中，不是彼此独立的按钮。

两阶段人工确认是流程的关键：prepare 阶段产出结构化材料后暂停，用户可对每个字段选择确认、修改或排除，对每张论点卡片选择采用或排除，并选择输出类型与章节结构；compose 阶段才据此生成内容。

引用与质量校验包含引用编号白名单校验、句子与证据的字符重合度检查，以及写作质量多维评分，评分维度包括主题句覆盖、分析句比例、论证动作完整性、重复率、段落差异度与连接词多样性。

### 技术边界

当前的检索增强是章节感知与规则驱动的结构化检索，不是向量数据库检索，没有使用 Embedding、FAISS、Chroma、Milvus 或 Qdrant。把这一层做成向量检索是后续可选项，但在科研场景里可追溯比召回的多样性更重要，因此优先保证证据能落回原文与结构化字段。

## 三、项目二：评测与审查

### 它解决什么问题

生成类产品普遍缺少效果度量。项目二用真实论文语料与真实模型替代人工编写的测试集，让效果好不好变成可量化、可复现、可归因的结论。它只处理真实数据，没有模拟用例或离线演示。

### 三层九项指标

检索层衡量证据找没找到、排得够不够前。

| 指标 | 判定标准 | 验收线 |
| --- | --- | --- |
| 块级命中率 Hit@K | 金标准块是否出现在前 K 个召回结果，K 默认 3 | 不低于 90% |
| 论文级命中率 Hit@K | 金标准所属论文是否有任意块进入前 K，补偿切块边界误差 | 100% |
| MRR | 金标准块排名倒数的均值，衡量排序质量 | 趋势指标，无硬线 |

问答层衡量答得对不对、引用有没有编。

| 指标 | 判定标准 | 验收线 |
| --- | --- | --- |
| 答案正确率 | 判定器对照标准证据判断，证据里有答案却拒答算失败 | 不低于 80% |
| 无效引用数 | 引用编号超出实际检索范围的条数，客观指标 | 必须为 0 |
| 证据覆盖率 | 回答覆盖了标准证据中多少句子，重合度阈值 0.25 至 0.3 | 趋势指标，无硬线 |

产出层衡量观点有没有依据，全部为句子级。

| 指标 | 判定标准 | 验收线 |
| --- | --- | --- |
| 论断句可追溯率 | 句子与所引证据重合度不低于 0.15 记为可追溯 | 不低于 85% |
| 未标注引用率 | 没有标注来源的文献事实句占论断句的比例 | 不高于 10% |
| 引用可疑率 | 重合度低于 0.15 的引用句，须经语义核实，属筛选器而非终判 | 可疑句须完成核实 |

句子先分三类再统计：文献事实句、作者分析句、说明句，只有事实句要求标注来源。不分类会让口径失真，实测中未标注引用率会从真实的 28.9% 虚高到 57%。

### 关键参数

| 参数 | 取值 |
| --- | --- |
| 切块长度 | 720 字 |
| BM25 参数 | k1 = 1.5，b = 0.75 |
| 相关性权重 | BM25 归一化 45% 加判别词覆盖 20% 加主题锚点 35% |
| 最终排序 | 相关性 55% 加文献质量 45% |
| 自动停用词阈值 | 文档频率超过 25% |
| 召回规模 | max(20, top_k 乘 6) 后重排 |
| 重排长度惩罚 | 块长度的 0.35 次方 |
| 引用可追溯阈值 | 二元组重合度 0.15 |
| 判定温度 | 0，保证可复现 |
| 判定重试 | 最多 3 次 |

### 运行方式

```bash
# 真实语料评测：自动出题、真实检索、真实模型、语义判定
python -m evaluation.run_realcorpus --limit 15
python -m evaluation.run_realcorpus --reuse --limit 15

# 产出审查：检查本项目真实运行记录的引用与归因问题
python -m evaluation.audit_project --list
python -m evaluation.audit_project
python -m evaluation.audit_project --verify
```

详细说明见 评测与审查说明.md。

## 四、内置高质量文献库

检索环节优先查本地语料库，命中足够就跳过在线请求，减少 OpenAlex 调用；命中不足才回退联网。

| 项目 | 规模 |
| --- | --- |
| 论文总数 | 3635 篇 |
| 中文与英文 | 135 篇与 3500 篇 |
| 覆盖期刊 | 44 个 |
| 年份范围 | 2018 至 2026 |
| 已有全文 | 16 篇，其余为摘要级证据 |

英文覆盖生态与环境类（Ecosystem Services、Landscape and Urban Planning、Journal of Environmental Management、Ecological Indicators、Nature Sustainability 等）与人工智能及信息系统类（Nature Machine Intelligence、JMLR、Artificial Intelligence、IEEE TPAMI、MIS Quarterly 等）。中文来自经过核验的 10 本核心期刊，包括生态学报、自然资源学报、软件学报、计算机研究与发展、中国科学信息科学、中国环境科学等。

### 期刊质量核验

中文期刊在 OpenAlex 里存在同名空壳条目：名称正确，但收录量与被引量极低、摘要为空。核验方式是对同一本期刊分别用中文名与英文名检索，比对收录量、被引量与 h 指数。第一轮核验 22 本期刊，只有 10 本指标正常，另外 12 本为空壳条目，例如计算机学报 h 指数为 1、地理学报仅 433 篇。清理前先做了文件备份，判定明细保存在 data/journal_audit_decision.json。

### 从摘要扩展到全文

摘要级证据撑不起方法、数据与设计这些字段。实测同一套抽取规则下，摘要级九字段覆盖率是 43%，换成全文后达到 100%。全文有两条通道。

```bash
# 自动通道：只抓开放获取论文，内置出版商黑名单，ScienceDirect 等对程序化下载返回 403
python fetch_fulltext.py --status
python fetch_fulltext.py --source unpaywall --limit 50

# 手动通道：学校图书馆合法获取的 PDF 直接入库
mkdir -p pdf_inbox
cp ~/Downloads/*.pdf pdf_inbox/
python ingest_pdfs.py
```

自动通道抽样 40 篇的成功率约为四成，因此提升全文覆盖率最实际的办法是用手动通道把常读的文献批量入库。详细说明见 本地文献库说明.md。

## 五、快速开始

```bash
pip install -r requirements.txt
cp .env.example .env      # 或直接在项目根目录新建 .env 并填写模型配置
streamlit run app.py
```

浏览器打开 http://localhost:8501，侧边栏「功能」可切换到「评测与审查」。

### 环境变量

```env
OPENAI_BASE_URL=http://127.0.0.1:15721/v1
OPENAI_API_KEY=
LLM_MODEL=deepseek-chat
LLM_MODEL_FAST=
LLM_MODEL_WRITING=
P4_LLM_ATTEMPTS=3
P4_LLM_STRICT=true
```

env 文件不会入库，请勿把密钥写入代码或提交到仓库。

### Docker 与云平台

```bash
docker build -t p4-literature-assistant .
docker run --env-file .env -p 8501:8501 p4-literature-assistant
```

容器会读取 PORT 环境变量，适配 Railway 等平台。

## 七、实测结果

检索策略基准来自 30 条真实问题，同一批问题横向对照，表内为 Hit@3 与 MRR。

| 策略 | 块 360 | 块 480 | 块 720 |
| --- | --- | --- | --- |
| 原始问题 | 80.0% / 0.700 | 80.0% / 0.656 | 80.0% / 0.733 |
| 双语扩展 | 100.0% / 0.800 | 96.7% / 0.764 | 96.7% / 0.839 |
| 双语扩展加 IDF 重排 | 93.3% / 0.833 | 100.0% / 0.767 | 100.0% / 0.844 |
| 多路 RRF 融合 | 63.3% / 0.507 | 63.3% / 0.473 | 60.0% / 0.493 |

跨语言查询扩展把块级命中率从 66.7% 提升到 93.3%。多路 RRF 融合实测反而最差，原因是中英文单独检索时英文查询引入大量错误候选，融合过程稀释了正确结果，这个负向结论也记录在案。

产出审查的一次真实运行结果：主题为生态系统文化服务与景观评估，3 篇论文、初稿 5613 字，正文引用 35 处、无效引用 0 处、没有论文被漏引；71 个句子中论断句 45 句、作者分析句 24 句、说明句 2 句；未标注引用的文献事实句 13 句，占论断句的 28.9%。审查同时定位出生成环节中事实句缺少来源标注这一具体缺陷，直接转化为下一条迭代需求。

## 八、已知局限

扫描版 PDF、复杂双栏、公式与表格仍可能解析不完整。在线检索受网络与接口额度影响，OpenAlex 可能出现限流。中文文献在 OpenAlex 的摘要覆盖偏低，导致中文侧证据深度不足。评测的答案正确性依赖模型判定，判定器偏宽松的可能性尚未用人工抽样量化。评测结论只适用于当前语料覆盖的范围，不能外推。

## 九、迭代方向

证据深度方面，扩大全文覆盖，把摘要级证据升级为全文级证据，直接提升九字段覆盖率与评审分。归因完整性方面，为生成环节增加无来源事实句的自动补标，压低未标注引用率。评测可信度方面，用人工抽样统计自动判定与人工判定的一致率，校准判定器。中文覆盖方面，重新定位 12 本空壳期刊在 OpenAlex 中的真实条目。检索增强方面，在关键词检索之外引入向量召回或重排，作为补充通道而非替换。导出能力方面，支持 DOCX 与 PDF 导出以及 GB/T 7714、APA 等规范引用格式。

## 十、使用边界

本项目定位为论文前期的辅助工具，不承诺生成可直接提交的最终论文。使用者仍需回到原文核对观点、检查作者年份与 DOI、判断研究空白是否成立，并按学校要求调整引用格式。生成内容必须经过人工审核。
