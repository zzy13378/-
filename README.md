\# 📚 科研文献整合与结构化写作助手



面向科研新手的 AI 文献整合工具，帮助用户将已收集的多篇论文进行解析、去重、分类、比较，并生成可追溯的文献综述或研究背景初稿。



\## 一、项目背景



科研新手在前期通常已经找到很多论文，但仍然面临以下问题：



\- 不知道如何对不同论文进行分类；

\- 难以快速提炼研究问题、研究方法和主要结论；

\- 只能按照论文顺序进行简单总结，无法形成主题化分析；

\- 难以发现不同研究之间的差异、局限和研究空白；

\- 担心 AI 生成内容缺少真实文献依据。



本项目聚焦于“多篇文献整合后的结构化写作辅助”，而不是替代用户直接完成论文。



\## 二、目标用户



\- 本科生、硕士生等科研新手；

\- 已经收集了约 3-20 篇相关论文的用户；

\- 正在撰写研究背景或文献综述的用户；

\- 需要快速完成论文前期材料整理的用户。



\## 三、核心使用场景



例如，用户正在研究“大语言模型智能体在科研场景中的应用”，已经下载了多篇相关论文，但不知道：



1\. 这些论文分别研究了什么问题；

2\. 采用了哪些技术或研究方法；

3\. 得出了哪些结论；

4\. 不同论文之间有哪些共同点和差异；

5\. 当前研究还存在哪些不足；

6\. 如何将这些材料组织成文献综述结构。



用户上传论文并输入研究主题后，系统会自动完成文献解析、主题归纳、论文比较、研究空白提炼和初稿生成。



\## 四、核心功能



\### 1. 多格式文献上传



支持批量上传：



\- PDF

\- Word（DOCX）

\- TXT

\- Markdown

\- JSON

\- CSV



系统会尝试提取：



\- 论文标题；

\- 作者；

\- 发表年份；

\- 摘要；

\- DOI；

\- 正文内容；

\- 页数及解析状态。



\### 2. 文献去重



系统支持基于 DOI 和论文标题进行去重，避免同一篇论文重复参与分析。



\### 3. OpenAlex 真实论文数据库检索



系统接入 OpenAlex 论文数据库，可根据研究主题补充相关论文信息。



在线检索主要用于：



\- 补充用户尚未上传的相关文献；

\- 获取论文标题、作者、年份、摘要和 DOI；

\- 在用户文献数量不足时提供基础研究资料。



\### 4. 多 Agent 文献分析流程



系统采用四阶段 Agent 工作流：



```text

研究规划

&#x20;  ↓

文献调研与主题归纳

&#x20;  ↓

结构化写作

&#x20;  ↓

来源评审与质量检查

```



具体包括：



\- Planning Agent：明确研究问题并规划输出结构；

\- Research Agent：提炼主题、研究方法、研究结论、局限和研究空白；

\- Writing Agent：生成带有文献来源标识的研究背景或文献综述初稿；

\- Critic Agent：检查引用覆盖、内容完整性和潜在问题。



\### 5. 结构化结果输出



系统会输出：



\- 已纳入的论文来源；

\- 主题归纳；

\- 文献比较矩阵；

\- 研究空白；

\- 文献综述或研究背景初稿；

\- 评审得分；

\- 缺失来源及修改建议。



\### 6. 报告下载



支持将完整分析结果导出为 Markdown 报告，便于继续修改或复制到论文写作工具中。



\## 五、产品价值



本项目主要解决的是“找到论文之后如何整合”的问题。



相较于只提供论文搜索、引用关系图谱或单篇论文问答的工具，本项目更关注：



\- 降低多篇文献的阅读和整理成本；

\- 帮助科研新手从逐篇总结转向主题化分析；

\- 将论文信息转化为研究问题、比较关系和写作结构；

\- 提高 AI 生成内容的来源可追溯性；

\- 为论文前期写作提供可编辑的结构化材料。

\## 八、本地运行



\### 1. 安装依赖



```bash

pip install -r requirements.txt

```



\### 2. 配置环境变量



在项目根目录创建 `.env` 文件：



```env

OPENAI\_API\_KEY=你的模型API\_KEY

OPENAI\_BASE\_URL=你的模型服务地址/v1

LLM\_MODEL=你的模型名称

```



示例：



```env

OPENAI\_API\_KEY=sk-xxxx

OPENAI\_BASE\_URL=https://api.openai.com/v1

LLM\_MODEL=gpt-4o-mini

```



不要将 `.env` 上传到 GitHub。



\### 3. 启动项目



```bash

streamlit run app.py

```



浏览器打开：



```text

http://localhost:8501

```

\## 十一、AI 输出边界



本项目定位为论文前期的辅助工具，不承诺自动生成可以直接提交的最终论文。



用户仍需：



\- 回到原文核对论文观点；

\- 检查作者、年份和 DOI；

\- 判断研究空白是否成立；

\- 根据学校格式要求修改引用；

\- 对 AI 生成内容进行人工审核。



\## 十二、当前限制



\- 扫描版 PDF 如果没有文字层，可能无法直接提取正文；

\- PDF 排版异常时，部分文本可能提取不完整；

\- 复杂表格、公式和图片内容暂未进行完整结构化解析；

\- 当前报告主要导出为 Markdown；

\- 在线论文检索受网络和接口可用性影响；

\- 生成质量与上传文献的完整度、模型能力有关。

\## 十四、项目定位



```text

不是：自动替用户完成论文

而是：帮助用户把分散的多篇论文整合成可理解、可比较、可追溯的写作材料

```
